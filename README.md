# AI Geo Quest

AI Geo Quest — веб-приложение на Go, которое генерирует интерактивные городские квесты с помощью ИИ на основе географического положения пользователя.

Пользователь выбирает точку на карте или передаёт свою текущую геолокацию, после чего система анализирует окружение (тип местности, объекты рядом) и создаёт тематический квест: приключенческий, исторический или исследовательский.

---

## Возможности (MVP)

* Генерация текстовых квестов по координатам
* Использование карт и геоданных (OpenStreetMap)
* Интеграция LLM для генерации заданий
* Веб-интерфейс с картой
* Без регистрации и хранения данных

---

## Архитектура

Приложение построено по принципам разделения ответственности и приближено к чистой архитектуре.

### Основные компоненты

* Frontend — карта, выбор координат, отображение квеста
* Backend (Go) — REST API и бизнес-логика
* Maps API — получение информации о местности
* LLM — генерация квестов

```
Browser
  ↓
Frontend (HTML / JS / Map)
  ↓ HTTP
Go Backend (API)
  ↓
Maps API (OSM)
  ↓
LLM (AI)
```

## Domain-модель

### Сущности

#### Quest

```go
type Quest struct {
    ID       string  // уникальный идентификатор
    Title    string  // название квеста
    Intro    string  // вводный текст
    Tasks    []Task  // список заданий
    Location Location // исходная точка квеста
}
```

#### Task

```go
type Task struct {
    ID   int    // номер задания
    Text string // описание задания
    Hint string // подсказка
}
```

#### Location

```go
type Location struct {
    Latitude  float64 // широта
    Longitude float64 // долгота
    Name      string  // название места или района
    Type      string  // тип местности (парк, исторический центр, туристическая зона)
}
```

### Пример квеста

```go
quest := Quest{
    ID: "qst_001",
    Title: "Тайна старых дворов",
    Intro: "Вы оказались в старом районе города, где каждый двор хранит свои секреты.",
    Location: Location{
        Latitude: 59.9343,
        Longitude: 30.3351,
        Name: "Старый город",
        Type: "historical_center",
    },
    Tasks: []Task{
        {ID: 1, Text: "Найди старую арку рядом", Hint: "Она старше 100 лет"},
        {ID: 2, Text: "Сделай фотографию памятника", Hint: "Он находится на главной площади"},
        {ID: 3, Text: "Определи год постройки здания с колоннами", Hint: "Смотри на табличку у входа"},
    },
}
```

## Логика реализации проекта (обновлено)

Ниже описаны основные шаги разработки с вопросами, на которые мы отвечаем на каждом этапе. Добавлены детали про сервис и интерфейсы.

### 1. Domain-модель

**Что делаем:** Определяем структуры Quest, Task, Location, UserSignal и отдельную сущность TaskAnswer, описывающую правила проверки ответа

**Обновление:** `TaskAnswer` выделен в отдельную доменную сущность. `Task` содержит ссылку на `TaskAnswer`, а не конкретный пользовательский ответ.

**Зачем:**

* поддержка разных типов заданий (тест, текст, фото, оффлайн)
* отсутствие логики ИИ в домене
* возможность отложенной и асинхронной проверки

**Вопросы:**

* Какие типы ответов поддерживает система?
* Какие из них проверяются автоматически, а какие — позже?
* Где проходит граница между доменом и AI/service?

**Доменные структуры (пример):**

```go
// Task — задание квеста
type Task struct {
    ID     int
    Text   string
    Hint   string
    Answer TaskAnswer
}

// TaskAnswer — описание ожидаемого ответа и правил проверки
type TaskAnswer struct {
    Type       string   // choice | text | photo | offline
    Expected   string   // ожидаемое значение (если применимо)
    Options    []string // варианты ответа для тестов
    Evaluation string   // стратегия проверки (exact, fuzzy, ai)
}
```

**Пример:**

```go
Task{
    ID:   1,
    Text: "Сфотографируй здание с колоннами",
    Hint: "Оно находится на главной площади",
    Answer: TaskAnswer{
        Type:       "photo",
        Evaluation: "ai",
    },
}
```
